# Music Genre Concept-Bottleneck Model — All Branches Supervised

This PyTorch model performs multilabel music genre classification with a shared
log-Mel CNN and four supervised concept branches: instrument, rhythm, timbre, and
harmony. The predicted branch concepts are fused by a gated fusion layer to
predict six genres.

## Genre results

| Split | Tracks | Macro average precision | BCE loss |
|---|---:|---:|---:|
| Validation | 1,099 | 0.7660 | — |
| Test | 1,098 | 0.7356 | 0.2975 |

The checkpoint selected by validation genre macro average precision is epoch 20.
The training split contains 5,127 tracks.

## Test branch results

| Branch | Primary metrics |
|---|---|
| Instrument | macro AP 0.2441; micro AP 0.3877; macro F1 0.0400; micro F1 0.1656 |
| Rhythm | standardized MAE 0.4358; RMSE 0.6491; macro R² 0.5736 |
| Timbre | standardized MAE 0.3178; RMSE 0.5610; macro R² 0.7008 |
| Harmony | standardized MAE 0.4791; RMSE 0.6940; macro R² 0.4704 |

Instrument is highly imbalanced, so its binary accuracy (`0.9243`) should not be
used alone; average precision and F1 are more informative. Complete per-tag and
per-feature results are stored in `results.json`.

## Outputs

The genre order is:

```text
classical, electronic, folk, hiphop, jazz, rock
```

The harmony branch predicts these standardized song-level descriptors:

```text
tonal_concentration_mean, tonal_concentration_std,
chroma_entropy_mean, chroma_entropy_std,
chroma_flux_mean, chroma_flux_std,
tonnetz_movement_mean, tonnetz_movement_std,
valid_tonal_ratio, tonnetz_01_mean, tonnetz_02_mean, tonnetz_03_mean
```

The checkpoint includes the 41-instrument vocabulary, rhythm/timbre/harmony
standardizers, all branch weights, fusion weights, and preprocessing metadata.

## Input preprocessing

- Sample rate: 16,000 Hz
- Log-Mel bands: 128
- Hop length: 512 samples
- Window duration: 15 seconds
- Centered STFT: yes
- Maximum sampled windows per track: 12
- Window frame capacity: 1,366

Preprocessing must match these settings. The model consumes log-Mel arrays with
window masks, valid-frame counts, and window start times generated by the project
data contract.

## Loading the checkpoint

The exact implementation is in the
[music-genre-classification repository](https://github.com/tharu-jwd/music-genre-classification/tree/83616d8).
Use source revision `83616d8` for checkpoint compatibility.

```python
import torch

checkpoint = torch.load("best.pt", map_location="cpu", weights_only=False)

# Available component state dictionaries:
# checkpoint["encoder"]
# checkpoint["instrument_head"]
# checkpoint["rhythm_head"]
# checkpoint["timbre_head"]
# checkpoint["harmony_head"]
# checkpoint["fusion_model"]
```

Instantiate the modules as in `scripts/train_joint.py`, restore each state
dictionary, call `eval()`, and apply sigmoid to the fusion logits for genre
probabilities. The checkpoint includes optimizer state and non-tensor metadata;
only load it from a trusted source.

## Training details

- Run: `joint-l4-b4-20ep-all-supervised`
- GPU: NVIDIA L4
- Epochs: 20
- Batch size: 4
- Optimizer: AdamW
- Initial learning rate: 0.0003
- Scheduler: cosine annealing
- Selection metric: validation genre macro average precision
- Source table: `vector-dataset-normalized.csv`

The joint objective uses genre BCE, instrument BCE, and masked Smooth L1 losses
for rhythm, timbre, and harmony. Continuous target standardizers are fitted only
on the training split. Ground-truth concept vectors are never passed into fusion.

## Intended use and limitations

This checkpoint is intended for coursework, research, reproducibility, and branch
architecture experiments. It is not calibrated for production decisions. Results
are from one train/validation/test split and may not transfer to other music
collections. Genre and instrument labels are multilabel and imbalanced. Harmony
targets are deterministic song-level tonal descriptors, not human chord labels or
12-bin pitch-class chroma distributions.
